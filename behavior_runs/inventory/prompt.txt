Create a multi-module Python inventory management system with the following features:

1. **Category model** — id, name (unique), description, reorder_threshold (optional int)
2. **Product model** — id, sku (unique), name, category_id (FK), price_cents (int), stock_qty (int), low_active (optional bool, default False, whether the product is still sold)
3. **CategoryRepository** — SQLite storage with CRUD + find all products belonging to a category
4. **ProductRepository** — SQLite storage with CRUD + find products by category + find low-stock products (stock_qty below reorder_threshold) + aggregate total stock value by category
5. **InventoryService** — business logic:
   - add_product(sku, name, category_id, price_cents, stock_qty): validates the category exists and the sku is unique, then adds the product
   - update_product(id, data): updates a product's fields
   - delete_product(id): deletes a product by ID
   - get_product_by_id(id): returns a single product by its ID
   - list_products(category_id (Optional[int]), low_only (Optional[bool])): lists products filtered by optional category and optionally only low-stock ones; no filters returns all products
   - restock(id, qty): increases a product's stock_qty
   - low_stock_report(): returns products whose stock_qty is below their category's reorder_threshold
   - stock_value_by_category(): returns the total price_cents * stock_qty per category
6. **CLI interface using click** with nested command groups:
   - `product add --sku --name --category --price --stock [--stock]`
   - `product list [--category] [--low-only]`
   - `product update --id [--name] [--price] [---category]`
   - `product delete --id`
   - `product restock --id --qty`
   - `product report low-stock`
   - `product report value`
   - `category add --name [--description] [--threshold]`
   - `category list`
   - `category update --id [--name] [--description] [--threshold]`
   - `category delete --id`

Use type hints throughout. Use SQLite with foreign keys enabled. All monetary values must be stored as integers (cents) to avoid floating-point issues. All IDs must be auto-incremented primary keys that are optional (default None) in the domain models. Implement proper error handling with custom exception classes: CategoryNotFoundError, ProductNotFoundError.
