Create a multi-module Python library management system with the following features:

1. **Book model** — id, title, isbn (unique), published_year, available_copies (default 1)
2. **Author model** — id, name, birth_year, biography
3. **Member model** — id, name, email (unique), membership_date, is_active (default True)
4. **Loan model** — id, book_id (FK), member_id (FK), loan_date, due_date, return_date (nullable), status (active/returned/overdue)
5. **BookRepository** — SQLite storage with CRUD + search by title/author/isbn + filtering by available copies
6. **AuthorRepository** — SQLite storage with CRUD + find books by author
7. **MemberRepository** — SQLite storage with CRUD + find active/inactive members
8. **LoanRepository** — SQLite storage with CRUD + find active loans, overdue loans, member loan history, book loan history
9. **LibraryService** — business logic:
   - borrow_book(member_id, book_id): checks availability, creates loan, decrements copies
   - return_book(loan_id): sets return_date, updates status, increments copies
   - get_overdue_loans(): returns loans past due_date
   - renew_membership(member_id): toggles is_active
   - search_books(query): searches across title/author/isbn
10. **CLI interface using click** with commands:
   - `library book add --title --isbn --author-id --published-year --copies`
   - `library book list [--author] [--available-only]`
   - `library book search --query`
   - `library member add --name --email`
   - `library member list [--active-only]`
   - `library borrow --member-id --book-id`
   - `library return --loan-id`
   - `library overdue`
   - `library member history --member-id`

Use type hints throughout. Use SQLite with foreign keys enabled. The database schema must enforce referential integrity with CASCADE deletes. Follow clean architecture with proper separation of concerns. All IDs must be auto-incremented primary keys that are optional (default None) in the domain models.
